# M3: moderation

Moderators review flagged and triaged items, act on them, and log every action
publicly under `/moderations`. Moderator pages live under `/mod`, admin pages
under `/admin`. AI triage reads every new submission and comment when an
Anthropic API key is configured, and is off without one. The design is in
`0001-design.md`, sections 8 and 9.

## Done when

- `threaded role grant DID admin` makes the first admin from the droplet's
  shell.
- A moderator removes and restores a story and a comment, locks a story,
  merges one story into another, bans and unbans a DID, and writes a note.
  Each action except the note appears on `/moderations` with its reason.
- An item with 3 flags appears in the Flagged tab of `/mod`.
- An admin edits a tag, grants and revokes a role, changes a setting, and
  saves a rules version on `/admin`.
- Without an API key, nothing calls the model and `/admin` says triage is off.
- With a key, a spam submission is held, shown to its author as held, logged
  with "triage" as the actor, and released or confirmed from the Holds tab.
- `make check` and `make a11y` pass, with the `/mod` and `/admin` pages in the
  audit.

## One way in

Every submission and comment enters the index through one function, whether
it comes from the web form or, from M4 on, from hydrant. A record written
straight to a PDS gets the same checks and the same triage as one written
through Threaded.

`accept` takes the author, the item, and its record URI and CID. In order, it:

1. Refuses banned DIDs and accounts whose level cannot post the item.
2. Applies the rate limits by level (design doc, §8).
3. Applies the tag rules: unknown tags dropped; no known tag left means not
   indexed; `show` needs `authored`; `ask` is text only; privileged tags.
4. Sends a URL posted in the last 30 days to the existing story.
5. Inserts the index row, or updates it when the record URI is already
   indexed. Threaded's own writes come back through hydrant, and they must not
   be indexed twice.
6. Adds the item to the triage queue in the same transaction, when triage is
   on.

The web handlers in `crates/web/src/write.rs` keep the parts that need a
person: the form, the PDS write, and deleting the record when `accept`
refuses or fails.

## AI triage

### On only with a key

| `THREADED_ANTHROPIC_KEY` | Triage |
|---|---|
| Unset | Off. No queue rows, no model calls, no holds. Flags and moderators work as usual. `/admin` shows "AI triage: off, no API key". |
| A key file path | On, once a rules version exists. |

The key is a file, like the OAuth and cookie keys, mode 0640, group
`threaded`. It never reaches the browser or the logs. Items indexed while
triage is off are not triaged later; turning it on never starts with a
backlog bill.

### Built for the key

The triage code is complete and tested in M3 even while no key is set:

- `Triager` has two variants, `Anthropic` and `Fake`, the same pattern as the
  record `Writer`. Route and worker tests use `Fake` with scripted verdicts.
- The request is built by a pure function and checked against a fixture, so
  the shape is tested without a network.
- With a key, `threaded triage check` sends one fixed test item and prints
  the verdict, the usage, and the cache hit. It is the by-hand check that the
  real API accepts the request.

### The call

`POST https://api.anthropic.com/v1/messages` with `reqwest`, headers
`x-api-key` and `anthropic-version: 2026-10-21`.

| Field | Value |
|---|---|
| `model` | The `triage_model` setting, default `claude-opus-5-5` |
| `system` | The current rules version, with `cache_control` on it |
| `messages` | One user turn: the item as JSON data (title, URL, domain, tags, text, parent comment, flag reasons, author level, tenure, prior removals) |
| `output_config` | `{"effort": "low", "format": {"type": "json_schema", "schema": ...}}` with the verdict schema from §9.2 |
| `max_tokens` | 2000 |

A refusal stop reason, a timeout (30 s), an HTTP error, or output that fails
the schema becomes `needs_human`. Errors count toward the provider error rate
on `/admin`.

### The worker

A task in the `threaded` process reads `triage_queue` oldest first, one item
at a time, and writes `triage_verdicts`. A restart picks up where it left off.
Spam at high confidence holds the item unless the circuit breaker is open;
then it becomes a suggestion. The breaker opens when confirmed holds fall below
the `hold_precision_floor` setting (95%) over the last 100 decided holds, and
an admin resets it.

Users who set "Keep my posts out of AI triage" go to the human queue with
verdict `needs_human` and no model call.

## Moderation state

Author deletes and moderator removals are different: an author delete is
final, a removal can be restored and is logged. Migration `0004_moderation.sql`
adds:

| Change | Holds |
|---|---|
| `stories`, `comments`: `held_at`, `removed_at`, `removed_by`, `removed_reason` | Holds and removals, apart from author deletes |
| `users`: `triage_opt_out` | The consent setting |
| `triage_queue` | Items waiting for the worker |
| `triage_verdicts` | Verdict, rule, confidence, explanation, model, rules version, and the moderator's decision |
| `rules_versions` | Rules text, author, time; the newest is current |
| `settings` | Key and value, for everything on `/admin/settings` |
| `suggestions` | Title and tag edits proposed by users with karma 10 or more |

Listings, search, profiles, and story pages hide held and removed items.
Authors still see their own, marked "held for review: spam (automated)" or
"removed by a moderator: REASON".

## Access

| Path | Needs | Otherwise |
|---|---|---|
| `/mod`, `/mod/...` | Moderator or Admin | Signed out: sign in. Signed in: 403, "Moderators only." |
| `/admin`, `/admin/...` | Admin | The same, "Admins only." |
| `/moderations`, `/moderations/stats` | Nobody | Public |

Every action is a POST with the CSRF token and a required reason. The role is
read from the database on each request, so a revoked moderator loses access at
once.

`threaded role grant DID moderator|admin` and `threaded role revoke DID` work
from the shell. They take a DID, not a handle: a handle can change hands, and
a DID cannot. The DID must have signed in once. The mod log records them with
"console" as the actor.

## Pages

The layout and contents are in the design doc, §9.7 and §9.8.

| Route | Page |
|---|---|
| `/mod` | Queue with tabs: Holds, Flagged, Suggestions, Edits (user suggestions). Each tab shows its count. |
| `/mod/s/{id}`, `/mod/c/{id}` | Item review: the item, revisions, flags with flaggers, the triage verdict, actions, its mod log |
| `/mod/u/{handle}` | User review: identity, standing, activity, notes, ban, role badges |
| `/moderations` | The public log, paginated |
| `/moderations/stats` | Hold confirmations and suggestion agreement |
| `/admin` | Health: triage on or off, queue depth, provider errors, queue counts, hold precision, breaker state with reset |
| `/admin/tags` | Every tag and its flags; create and edit |
| `/admin/people` | Moderators and admins, grant and revoke; role badges |
| `/admin/settings` | Level thresholds, rate limits, flag windows and limits, hold-precision floor, triage model |
| `/admin/rules` | The rules triage reads, with version history |

Every page works without JavaScript. Queue rows are `<article>` elements with
real buttons, and the optional `j`/`k` keys are off by default.

## Tasks

In order; each lands with its tests.

1. **`accept`.** Move the M2 checks out of the handlers into `accept`, with
   store tests for each refusal and for re-indexing a known record URI. The
   M2 route tests pass unchanged.
2. **Migration and roles.** `0004_moderation.sql`; `role grant` and `role
   revoke`; `/mod` and `/admin` access checks.
3. **Mod log and actions.** Remove, restore, lock, unlock, edit title and
   tags, merge, ban, unban, notes. Bans also refuse writes in `accept`.
   `/moderations`.
4. **Queue and reviews.** `/mod` tabs, item review, user review.
5. **Settings.** The `settings` table feeds the thresholds, limits, and flag
   windows that are constants today. `/admin/settings`, `/admin/tags`,
   `/admin/people`, role badges.
6. **Suggestions.** Users with karma 10 or more suggest title and tag edits;
   moderators accept or dismiss them from the Edits tab.
7. **Triage.** `Triager`, the request builder, the worker, holds, the
   breaker, the consent setting, `/admin/rules`, `/admin` health,
   `/moderations/stats`, `threaded triage check`.
8. **Docs and deploy.** README, design doc, deploy doc (the key file and
   `role grant`), deck.
