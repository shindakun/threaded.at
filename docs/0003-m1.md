# M1: sign-in

M1 lets anyone with an atproto account sign in to threaded.at and out again.
Nothing is written to anyone's repo yet; that starts in M2. The design is in
`0001-design.md`, sections 2.1 to 2.7.

## Done when

- A Bluesky-hosted account signs in on threaded.at, sees its handle in the
  header, and signs out. Sign-out revokes the token at the account's server.
- An account on a self-hosted PDS does the same.
- The same flow works on `127.0.0.1` with the localhost development client.
- `https://threaded.at/oauth-client-metadata.json` and `/oauth/jwks.json`
  serve, and bsky.social accepts a pushed authorization request from the
  hosted client.
- The browser holds one cookie with a session key and no token.
- `make check`, `make a11y`, and CI pass.

## Scope

M1 requests `atproto` and nothing else, and its client metadata declares only
`atproto`. M2 adds the submission and comment scopes when writing exists
(design doc, §2.2).

## Library

`jacquard-oauth` 0.12.2 provides:

| Need | Provided by |
|---|---|
| Confidential client metadata | `atproto_client_metadata` with a `Keyset`. Emits `private_key_jwt`, `ES256`, `jwks_uri`, and `dpop_bound_access_tokens`. |
| Signing key | `Keyset::generate_es256`. The private JWK set serializes to JSON and reloads with the same public key. |
| Authorization URL | `OAuthClient::start_auth` returns the URL and leaves the redirect to the caller |
| Host for the confirm page | `OAuthResolver::resolve_oauth`: the authorization server's metadata and the DID document, without starting authorization |
| Callback | `OAuthClient::callback` checks `state` and `iss`, exchanges the code, and verifies `sub` against the issuer |
| Storage | The `ClientAuthStore` trait: sessions keyed by DID and session ID, pending requests keyed by `state` |
| Sign-out | `OAuthSession::logout` revokes at the server and deletes the session |

Threaded covers three gaps:

- The callback accepts a token response with no `scope`. Threaded checks for
  `atproto` afterwards and discards the session if it is missing.
- The callback parses the server's `scope` with `expect`, so a malformed value
  panics. The OAuth routes run under `tower-http`'s `CatchPanicLayer`, which
  turns a panic into an error page.
- `OAuthClient::revoke` only deletes the local session. Sign-out uses
  `OAuthSession::logout`.
- The pushed request sends the client configuration's whole scope list and
  ignores per-request scopes. M1 has one scope set; M2's opt-in scopes each
  need their own client configuration.
- jacquard 0.12.2 pins `p256` 0.13 and with it `crypto-bigint` 0.5.5
  (RUSTSEC-2026-0387). Threaded builds patched copies on `p256` 0.14 from
  `third_party/`.
- There is no `prompt=create`. "Create an account on Bluesky" starts sign-in
  at `https://bsky.social`, whose sign-in page offers sign-up.

The published public key carries `kid` but no `alg` or `use`; bsky.social and
self-hosted PDSes accept it.

## Settings

| Variable | Meaning |
|---|---|
| `THREADED_PUBLIC_URL` | `https://threaded.at` in production. When unset, Threaded runs as the localhost development client. |
| `THREADED_OAUTH_KEY` | Path to the private JWK set. Production only. |
| `THREADED_COOKIE_KEY` | Path to the 64-byte key that encrypts and signs the session cookie |

`threaded keygen DIR` writes `oauth-key.json` and `cookie.key` into `DIR` with
mode 0600 and refuses to overwrite either. Production runs it once, into
`/etc/threaded/`.

## Tasks

In order; each lands with its tests.

1. **Keys and settings.** `threaded keygen`; settings parsed at startup; a
   clear startup error naming the missing file or variable.
2. **Migration `0002`.** `oauth_sessions (did, session_id, data, updated_at)`
   with the pair as primary key, and `oauth_requests (state, data,
   created_at)`. `data` is the library's JSON. Requests older than 15 minutes
   are deleted at startup and hourly.
3. **`SqliteAuthStore`** implementing `ClientAuthStore` over those tables.
4. **Metadata routes.** `GET /oauth-client-metadata.json` and
   `GET /oauth/jwks.json`, both from the library's output, cached for five
   minutes.
5. **Sign-in pages** (design doc, §2.6):
   - `GET /login`: the form.
   - `POST /login`: resolves with `resolve_oauth`, renders `/login/confirm`
     naming the authorization server's host, and the PDS host when it differs.
   - `POST /login/go`: calls `start_auth` and redirects with `303`. The
     pushed request happens here, so a slow reader never meets an expired
     `request_uri`. A changed authorization host re-renders the confirm page.
   - Unicode hosts show both forms, using `idna::domain_to_unicode` beside the
     ASCII host.
6. **Callback.** `GET /oauth/callback` runs the library callback, checks the
   `atproto` scope, verifies the handle both ways, upserts the `users` row,
   sets the session cookie, and redirects to the page sign-in started from.
   Failures render a page naming the host and the reason (design doc, §2.6
   step 3).
7. **Session cookie.** `PrivateCookieJar` from `axum-extra`. One cookie
   holding the DID and session ID: `__Host-threaded` with `Secure` in
   production, plain `threaded` on localhost, where the `__Host-` prefix
   would require HTTPS. `HttpOnly`, `SameSite=Lax`, `Path=/`, 30-day lifetime
   renewed on use. A request extractor loads the signed-in user, or none when
   the cookie or the stored session is gone.
8. **CSRF.** Every `POST`, sign-in forms included, carries a token that must
   match a `SameSite=Strict` cookie.
9. **Sign-out.** `POST /logout` calls `OAuthSession::logout`, clears the
   cookie, and returns to the front page.
10. **Header.** Signed out: "Sign in". Signed in: the handle, or the DID when
    the handle does not verify, and a "Sign out" button.
11. **Lookahead** (design doc, §2.7): `GET /login/typeahead?q=` proxying
    `app.bsky.actor.searchActorsTypeahead` with a 30-second cache and a per-IP
    limit, and the combobox script in the light DOM. The client IP comes from
    `X-Forwarded-For` only when the connection is from `127.0.0.1`.
12. **Deploy.** Keygen and settings in `0002-deploy.md`; `THREADED_PUBLIC_URL`
    in `threaded.env`.

## Tests

| Layer | What |
|---|---|
| Unit | Store round trips and expiry; scope check; host extraction and IDN display; cookie contents hold no token; CSRF rejects a missing or wrong token |
| Route | Metadata and JWKS match the expected JSON; `/login` renders; a forged callback `state` is rejected; signed-out and signed-in headers |
| Network, run by hand | `cargo test -- --ignored par_bsky`: a pushed authorization request to bsky.social with the localhost client succeeds and returns a `request_uri` |
| Accessibility | `/login` in `make a11y`; the confirm and error pages rendered in a test and audited from the HTML file |
| By hand | Sign in and out with a Bluesky account and a self-hosted account, on localhost and on threaded.at; VoiceOver and keyboard-only passes over the three sign-in pages |

## Decisions

- **Scope:** `atproto` only.
- **Session length:** 30 days from last use.
- **Unverified handles:** shown as the DID.
