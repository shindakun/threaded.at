# M2: writing

Signed-in users submit stories, comment, upvote, flag, and edit or delete what
they wrote. Submissions and comments are records in the author's repo; votes and
flags stay in Threaded's database unless the voter makes upvotes public. The
design is in `0001-design.md`, sections 3 to 9.

## Done when

- `steve.is.angstridden.net`, signed in to a local build, submits a link story
  and a text story, comments, replies, upvotes, flags, edits, and deletes. Each
  record appears in its repo under `at.threaded.dev.*`.
- The same on threaded.at writes `at.threaded.*`.
- Public upvotes write and delete `at.threaded.vote` records.
- Level limits, rate limits, tag rules, and flag windows hold.
- `make check` and `make a11y` pass.

## Namespaces

| Mode | Records |
|---|---|
| Production (`THREADED_PUBLIC_URL` set) | `at.threaded.submission`, `.comment`, `.vote` |
| Local (`THREADED_PUBLIC_URL` unset) | `at.threaded.dev.submission`, `.comment`, `.vote` |

Local builds against a real PDS never write production record types, so the
M4 indexer never reads test data. The PDS accepts both: `createRecord` with
`validate` unset checks only lexicons it knows.

## Scopes

| Client configuration | Scopes |
|---|---|
| Base, every sign-in | `atproto repo:<ns>.submission repo:<ns>.comment` |
| Public upvotes | The base plus `repo:<ns>.vote?action=create&action=delete` |

jacquard-oauth sends the configuration's whole scope list, so each row is its
own client configuration. Both share the client ID, key, and store. The
metadata document declares the union.

A session from M1 holds `atproto` alone and cannot write; signing out and in
again grants the M2 scopes.

## Writing records

`crates/auth` defines `com.atproto.repo.createRecord`, `putRecord`, and
`deleteRecord` as `XrpcRequest` types and sends them through the restored
`OAuthSession`, which handles DPoP and token refresh. A trait, `RecordWriter`,
wraps the three calls; tests use an in-memory implementation.

Write-through order:

1. Check the user's level, limits, and the input.
2. Write the record to the PDS.
3. Insert the index row with the record's URI and CID.

A PDS failure shows the error and indexes nothing. A database failure after a
successful write deletes the record and shows the error.

## Tasks

In order; each lands with its tests.

1. **Namespaces and scopes.** Record collection names from the mode; the two
   client configurations; the union in the metadata document.
2. **Record writer.** The three XRPC types, `RecordWriter`, the session
   implementation, the in-memory implementation.
3. **Markdown for user text.** The blog renderer with images and headings
   removed (design doc, §13).
4. **Submit**, `GET /submit` and `POST /submit`: title, URL, text, 1 to 5 tags,
   and "I wrote this". Duplicate URLs within 30 days go to the existing story.
   `show` needs `authored`; `ask` is text-only; privileged and
   `new_users_ok` tags follow §5.
5. **Story page.** The text body, the comment thread as nested lists of
   `<article>`, a comment form, and a reply page per comment.
6. **Votes.** `POST /vote` toggles an upvote; score, rank, and karma update
   in the same transaction. The button is a form with `aria-pressed`; a small
   script updates in place.
7. **Flags.** `POST /flag` with a reason; private; flag windows and score
   floors from §9.1. Authors see the reasons on their own items.
8. **Edit and delete.** Authors edit title, text, and tags; the URL only in the
   first hour. Edits write `putRecord` and keep the prior version in
   `story_revisions`. Deleting writes `deleteRecord`; a comment with replies
   leaves "[deleted]".
9. **Public upvotes.** A setting on `/settings`; turning it on asks whether to
    publish past upvotes; turning it off deletes the records.
10. **Profiles.** `/u/{handle}` lists a user's stories and comments.
11. **Limits.** Stories per day and comments per hour by level (§8), counted
    from the index.
12. **Tags.** `threaded tag add NAME --description TEXT [--boost N]` and
    `threaded tag list` until the admin pages in M3.

## Tests

| Layer | What |
|---|---|
| Unit | Record bodies match the lexicons; the namespace by mode; Markdown drops images and headings |
| Route, with the in-memory writer | Submit, comment, reply, vote, flag, edit, delete; each refusal (level, limit, tag rule, duplicate, window); CSRF on every form |
| Lexicon | Every record body the writer sends validates with `goat lex validate` |
| Accessibility | Submit, story with comments, reply, settings, and profile pages in `make a11y` |
| By hand | The "Done when" list with the test account, locally and on threaded.at |
