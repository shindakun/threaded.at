# M5: reader features

What makes Threaded comfortable to read every day: an inbox for replies,
"new" markers on threads, a saved list, hiding stories and tags, Atom feeds,
posting a story to Bluesky, and labels from atproto labelers. The design is in
`0001-design.md`, sections 3.1, 5, 9.5, and 11.

M5 also takes in three reader features from section 11 that no milestone
named: archive links, comment folding, and keyboard navigation. And it closes
the items `0007-test-sweep.md` left for M5.

## Done when

- A reply to your story or comment, from the web or from the network, shows
  in `/inbox` and in the unread count in the header; opening the inbox clears
  the count.
- A story you have read shows "3 new" when three comments arrive after your
  last visit.
- Saving, hiding, and filtering a tag change your listings and nobody else's.
- Every listing named in section 11 has an Atom feed that validates.
- With cross-posting turned on, ticking "Also post to Bluesky" on submit
  creates a Bluesky post with the title and story link.
- An account labelled `!takedown` or `!hide` by a site labeler is hidden from
  everyone; one labelled by a labeler you added is hidden from you.
- Archive links show on every link story; threads fold; `j`/`k` move through
  stories and comments once turned on in settings.
- `make check` and `make a11y` pass, and the browser scripts are tested.

## Saved, hidden, and filtered

The tables exist since `0001_init.sql`: `saved_stories`, `hidden_stories`,
`tag_filters`. All three are private and live only in Threaded's database;
none is a record.

| Feature | Where | Behavior |
|---|---|---|
| Save | A "save" link on every story row and page; `/saved` | Newest saved first |
| Hide | A "hide" link on every story row; `/hidden` to undo | Hidden stories leave every listing for that reader: front, newest, active, top, tags, domains, profiles, and search |
| Tag filters | `/settings` | A filtered tag's stories leave the same listings, except `/t/{tag}` itself and a search for `tag:` that tag |

A saved story stays on `/saved` when it is also hidden or filtered. A story
moderators removed takes no new save or hide, but an old one can still be
taken away.

The links are forms, so they work without JavaScript; `vote.js`'s pattern
updates them in place when it runs.

## Replies inbox

The inbox lists comments that reply to you: top-level comments on your
stories, and replies to your comments. Not your own comments, not deleted or
hidden ones, and not ones by accounts the network reports inactive. Comments
from the network count the same as comments from the web.

The unread count is the number of those newer than `users.inbox_read_at`.
Opening `/inbox` sets it to now. The header shows the count when it is above
zero, as text ("inbox (3)"), never as color alone. Unread replies on the
page say "new" in words.

A reply is dated by its record's `createdAt`, so one backfilled from the
network with an older date does not count as unread, though it is listed.
Accounts that existed before the inbox start with everything read; a new
account counts from when it was created.

## Read ribbons

`story_reads` holds, per reader and story, when the reader last opened the
story page. A listing row shows "N new" for comments created since then,
counting only comments the reader can see. Stories the reader never opened
show nothing. The reader's own comments do not count. Opening the story
page records the read; a later read never moves the time back. Each hour,
reads of stories older than the lock age (`lock_days`, 90 by default) are
dropped, since those stories take no new comments.

## Feeds

Atom 1.0 feeds, 30 entries each, at:

| Feed | Path |
|---|---|
| Front page | `/feed` |
| Newest | `/newest/feed` |
| A tag | `/t/{tag}/feed` |
| A domain | `/domain/{domain}/feed` |
| A user | `/u/{did}/feed`, by DID, like every account link |
| The blog | `/blog/feed` |

A feed is the signed-out view of its listing, so no reader's hides or tag
filters reach it. The front page feed follows the front page's ranking; the
tag and domain feeds are newest first, so a subscriber sees each new story
once. A user feed's address holds the DID, and a handle in its place
redirects there, so a subscription stays with the account. Entries link the
story's URL, or its page for a text post, with the discussion page as
`rel="replies"`. Characters XML 1.0 cannot carry are dropped, since one
would make the whole feed unreadable. Feed routes sit outside the cookie
layer and send `Cache-Control: public, max-age=300`. `feed` is a reserved
blog slug.

Each listing page links its feed with `<link rel="alternate"
type="application/atom+xml">` and a visible "Atom feed" link. Feeds need absolute URLs, so `AppState` gains
the public origin from `THREADED_PUBLIC_URL`, or `http://127.0.0.1:` with the
`THREADED_ADDR` port when unset; a value with a path or no scheme stops the
server at startup. Pages also gain `og:url` from it.

## Bluesky cross-post

Turning it on in `/settings` runs a second authorization that adds
`repo:app.bsky.feed.post?action=create` (design section 2.2), the same way
public upvotes add the vote scope. Public upvotes and cross-posting can each
be on or off, so a sign-in requests the scopes for whichever are on.

With it on, the submit form shows "Also post to Bluesky", unticked by default.
Ticked, Threaded writes the story's record, indexes it, then creates an
`app.bsky.feed.post` with the title as text and the story page as an
`app.bsky.embed.external` card. The post's AT-URI is stored on the story. A
failed Bluesky post does not undo the story; the story page tells the author
it was not posted and offers to try again. Only the author's own submissions
from the web are cross-posted, never records from the network.

As built:

- `Flow` is two flags, votes and Bluesky, so there are four client
  configurations, one per scope set. A grant asks for the session's current
  scopes plus the new one, so granting one never drops the other, and a
  later sign-in asks for the scopes of whichever features the account has
  on. Before this, signing in again from `/login` dropped the vote scope of
  a user with public upvotes.
- Cross-posting is offered only when the build writes `at.threaded.*`, a
  production build: a local build would post cards that link
  `127.0.0.1`.
- The card's description is the start of a text post, or "A link to
  DOMAIN, on Threaded."; a page preview's comment count would be out of
  date at once.
- A story readers cannot see, such as one held for a moderator, is not
  posted. The author sees why and can try again once it is visible. A
  story is posted at most once: trying again after a post was made does
  nothing.
- Threaded can create the post but not delete it; deleting the story leaves
  the post, and settings says so.
- `make lex-validate` checks a sample post against Bluesky's own lexicon,
  copied with its source commit into `crates/auth/tests/lexicons/`.
- `users.cross_post`, `stories.bsky_post_uri`, and `stories.bsky_post_error`
  come in `0011_cross_post.sql`.

## Labels

Section 9.5. Threaded reads account-level labels from labelers, and hides
content from accounts labelled `!takedown` or `!hide`.

- **Site labelers** are listed in `/admin/settings` by DID. The default is
  Bluesky's moderation service, `did:plc:ar7c4by46qjdydhdevvrndac`, whose
  labeler endpoint is `https://mod.bsky.app`; both were checked against the
  PLC directory for this plan.
- **Personal labelers** are added in `/settings` by DID. Their labels hide
  content only in that reader's view.
- Threaded subscribes to each labeler's `com.atproto.label.subscribeLabels`
  with a stored cursor, as it reads hydrant's stream, and keeps the current
  labels per account. A negation (`neg`) removes a label; an expired one
  (`exp`) stops counting.
- Each label's signature is checked against the labeler's `#atproto_label`
  key from its DID document. An unsigned or badly signed label is dropped and
  logged.
- A hidden account's author sees why, as for an inactive account, naming the
  labeler.

The exact message shapes, the signature format, and how a labeler's key
rotates are confirmed from the atproto specification and a cloned reference
implementation before task 8 starts.

## Archive links, folding, and keys

- **Archive links.** Every link story's page links to the Wayback Machine and
  archive.today copies of its URL: `https://web.archive.org/web/{url}` and
  `https://archive.today/newest/{url}`. Both were checked against the
  services: each takes the URL as it is, query included, and redirects to
  the newest copy, or answers 404 and offers to make one. The fragment is
  dropped, since it never reaches a server.
- **Comment folding.** `thread.js` gives each comment a "fold" button that
  hides its text and its replies and keeps its head. The folded comments
  are kept in the fragment as `#fold=ID,ID`, so a reload or a shared link
  keeps them. Without JavaScript there is no fold button and every comment
  stays open; a link to the comment's own thread, the first idea, would not
  fold anything.
- **Keyboard navigation.** `keys.js`: `j` and `k` move focus between stories
  and comments, skipping replies inside a folded thread, and `o` opens the
  story in focus. Keys typed into a form or pressed with Ctrl, Alt, or Cmd
  are left alone. Single-key shortcuts must be possible to turn off (WCAG
  2.2, 2.1.4), so they are off by default, turned on in `/settings`
  (`users.keyboard_shortcuts`, migration `0010`), and the script loads only
  for readers who turned them on.

## Testing the browser scripts

`scripts/a11y/` already drives Chrome with
[puppeteer-core](https://github.com/puppeteer/puppeteer). The same harness
gains behavior checks: vote and save in place, comment folding and the
fragment, `j`/`k` only when turned on, the sign-in typeahead with a fake
answer. This closes the `vote.js` and `login.js` item from the test sweep.

`behavior.mjs` runs after the page audit as a plain reader from the
fixture, whose upvotes are private so a vote writes no record. Chrome
resolves no host but the test server, so no check reaches the internet. The
folded and focused states also get an axe audit, in light and dark.
